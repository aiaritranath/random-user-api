# Random User API

A private, API-key-protected REST API that generates **synthetic random user profiles** in JSON. It is built with Node.js and deployed as a Vercel Serverless Function.

Generated profiles can include a name, gender, location, contact details, login fields, date of birth, registration details, placeholder ID values, profile-picture URLs, and a nationality code. The records are generated by this project and should be treated as fictional test data.

## Features

- Generate between **1 and 50** user profiles per request.
- Filter profiles by gender (`male` or `female`).
- Request a nationality using a two-letter country code.
- API-key authentication through an `x-api-key` header, a Bearer token, or a query parameter.
- CORS support for browser-based clients.
- JSON responses containing result data and metadata.
- Ready to deploy on Vercel.

## Tech Stack

- Node.js 18 or newer
- JavaScript (CommonJS)
- Vercel Serverless Functions

## API Endpoint

After deploying to Vercel, the main endpoint is:

```text
https://YOUR-PROJECT.vercel.app/api
```

The project also configures a rewrite from `/` to `/api`, so the deployment root can be used as an alias.

**HTTP method:** `GET`

All requests except `OPTIONS` must include a valid API key.

## Authentication

Set the `API_KEY` environment variable on the server. The API accepts the key using any one of these methods.

### Recommended: `x-api-key` header

```http
x-api-key: YOUR_API_KEY
```

### Authorization Bearer token

```http
Authorization: Bearer YOUR_API_KEY
```

### Query parameter

```text
?api_key=YOUR_API_KEY
```

Using a header is recommended because query parameters can be recorded in browser history, server logs, or analytics. **Never put a secret API key in frontend code that is shipped to users.** Calls from a public browser app should normally go through your own backend.

## Query Parameters

| Parameter | Required | Description | Example |
|---|---|---|---|
| `results` | No | Number of profiles to generate. Defaults to `1`; values are limited to `1–50`. | `results=5` |
| `gender` | No | Set to `male` or `female`. Any other or omitted value causes gender to be selected randomly. | `gender=female` |
| `nat` | No | Two-letter nationality code. Supported codes: `US`, `GB`, `CA`, `AU`, `IN`, `DE`, `FR`, `DK`, `UA`, `BR`. An unsupported code falls back to a randomly selected country. | `nat=IN` |
| `seed` | No | A string included in the response metadata. **It does not currently make the generated results reproducible.** | `seed=demo123` |

## Usage Examples

Replace `YOUR-PROJECT` and `YOUR_API_KEY` with your deployment URL and configured key.

### cURL

```bash
curl -X GET "https://YOUR-PROJECT.vercel.app/api?results=3&gender=female&nat=IN" \
  -H "x-api-key: YOUR_API_KEY"
```

### JavaScript (`fetch`)

```javascript
const response = await fetch(
  "https://YOUR-PROJECT.vercel.app/api?results=2&nat=GB",
  {
    method: "GET",
    headers: {
      "x-api-key": "YOUR_API_KEY",
    },
  }
);

if (!response.ok) {
  throw new Error(`API request failed: ${response.status}`);
}

const data = await response.json();
console.log(data.results);
```

## Error Responses

| HTTP status | Meaning | Typical cause |
|---|---|---|
| `200 OK` | Success | Profiles generated. |
| `401 Unauthorized` | Missing or invalid API key | Send a valid key using one of the supported authentication methods. |
| `405 Method Not Allowed` | Unsupported HTTP method | Use `GET`; `OPTIONS` is also handled for CORS preflight. |
| `500 Server Misconfigured` | Server key is not configured | Set `API_KEY` in the deployment environment. |

Error responses include an `error`, a `message`, and creator metadata.

## Run Locally

### 1. Requirements

Install [Node.js 18+](https://nodejs.org/) and the [Vercel CLI](https://vercel.com/docs/cli).

### 2. Get the project

Clone your GitHub repository, or extract this project and open a terminal in its root directory.

```bash
npm install
```

### 3. Configure the API key

Create a `.env.local` file in the project root:

```env
API_KEY=replace_this_with_a_long_random_secret
```

Do not commit `.env.local`. It is excluded by the provided `.gitignore`.

### 4. Start the development server

```bash
npm run dev
```

The configured script runs `vercel dev`. If the Vercel CLI is not installed, install it or run it with `npx vercel dev`.

Test the local endpoint (commonly `http://localhost:3000/api`):

```bash
curl "http://localhost:3000/api?results=2&nat=IN" \
  -H "x-api-key: replace_this_with_a_long_random_secret"
```

## Deploy to Vercel

1. Push the project to GitHub.
2. In [Vercel](https://vercel.com/), import the GitHub repository.
3. In the project's **Settings → Environment Variables**, add `API_KEY` with a strong, private value.
4. Deploy or redeploy the project so the environment variable is available to the function.
5. Call `https://YOUR-PROJECT.vercel.app/api` using your key in a request header.

Do not add the production key to your GitHub repository or expose it in a client-side application.

## Important Notes

- **Synthetic data only:** User details are randomly generated and are not verified identities or real contact records.
- **Generated IDs are not valid identifiers:** Fields labelled `SSN`, `Aadhaar`, or `CPR` are simulated placeholders. They must not be used for identity verification, financial transactions, or any real-world purpose.
- **Login values are for testing only:** Generated passwords and hashes are not intended to secure accounts or authenticate real people.
- **Profile images:** Image URLs point to portrait files hosted by [Random User Generator](https://randomuser.me/).
- **Rate limiting:** The current code does not implement rate limiting or usage quotas. Consider adding them before offering the API publicly.
- **Authentication:** The API key is checked by the server, but anyone who obtains the key can call the API. Keep it secret and rotate it if exposed.
- **CORS:** The current configuration permits requests from any origin. Restrict allowed origins if your deployment requires it.
- **Seed behavior:** The `seed` parameter is currently echoed in metadata only; it does not control random generation.
